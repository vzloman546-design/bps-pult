# БПС Пульт 2.1.0 — отчёт проверки

Дата проверки: 31.07.2026.

## Автоматические проверки

| Набор | Результат |
|---|---:|
| Конфигурации мероприятий | 9/9 |
| База знаний | 14/14 |
| Миграции, backup, ZIP, merge, undo и целостность | 15/15 |
| Контракты транзакций и переходов UI | 10/10 |
| Политика и изоляция service worker | пройдена |
| Синтаксис 7 JavaScript-файлов | пройден |

Проверены схемы 1, 2 и 3 с миграцией в схему 4, повторяющиеся и отсутствующие идентификаторы, повреждение ZIP, контрольные суммы, MIME-типы и размеры вложений, небезопасные data URL, выбор более новой записи при merge, связи задач с осмотрами, циклы разделов и конкурентно безопасная отмена удаления.

## Браузерные сценарии

На локальном тестовом origin выполнены:

- контролируемое обновление через waiting worker и кнопку «Обновить»;
- запуск приложения и чтение локальных данных при полностью остановленном HTTP-сервере;
- создание оборудования, мероприятия, связанной статьи, записи со связанной задачей и осмотра со связанной задачей;
- сохранение статуса «Не проверено» в чек-листе осмотра;
- удаление осмотра с атомарным очищением ссылки задачи;
- проверка целостности после удаления: 0 ошибок, 0 предупреждений;
- preview старой JSON-копии, миграция схемы 3 → 4 и merge через интерфейс;
- поиск статьи по обозначению связанного оборудования и названию мероприятия;
- переход из карточки осмотра в редактор после завершения анимации;
- сохранение фокуса после изменения чек-листа и раскрытия конфигуратора мероприятия.

## UI-аудит

Проверены 11 маршрутов на ширинах 320, 375, 390 и 430 px в светлой и тёмной темах — 88 маршрутных проверок.

Формы записи, задачи, техосмотра, оборудования, мероприятия и статьи проверены на 320 px. Сложные редакторы мероприятия и базы знаний проверены на всех четырёх ширинах в обеих темах. Для мероприятия раскрыты гейт, восемь турникетов, касса и смена; отдельно проверена карточка с 32 пунктами чек-листа.

Результат:

- `body.scrollWidth` и `main.scrollWidth` не превышают доступную ширину контента;
- bottom sheet не имеет внутреннего горизонтального overflow;
- нижняя навигация имеет `position: fixed` и нижнюю границу `0`;
- эффективные зоны касания не меньше 44×44 px;
- у видимых интерактивных элементов есть доступные имена;
- фон bottom sheet получает `inert` и `aria-hidden`;
- активный фокус остаётся внутри диалога и возвращается после закрытия;
- Escape закрывает диалог;
- светлая и тёмная темы используют одинаковую геометрию;
- рассчитанный контраст основных action-токенов: от 4.66:1 для обычного текста и от 7.03:1 для тёмной темы.

Числовые сводки: `reports/FULL-UI-AUDIT.json`, `reports/UI-VIEWPORT-RESULTS.json`, `reports/STABLE-TEST-METRICS.json`.

## Service worker

- версия кэша: `bps-pult-2.1.0`;
- `install` не вызывает `skipWaiting()`;
- активация ожидает сообщения `SKIP_WAITING`;
- активный worker открывает только собственный кэш и не использует глобальный `caches.match`;
- JS/CSS в `index.html` имеют версионные URL, поэтому старый worker не может ответить ресурсом 2.0.0 на запрос 2.1.0;
- навигация и ресурсы используют cache-first внутри активной версии;
- старые кэши удаляются только после контролируемой активации;
- отсутствие fallback `index.html` для JS/CSS исключает ответ HTML вместо ресурса.

## Что не проверено на реальном устройстве

Проверка выполнена во встроенном Chromium-браузере, а не в WebKit на физическом iPhone. На реальном устройстве ещё требуется подтвердить:

- системную строку iOS и фактические safe-area inset;
- камеру и обработку HEIC-фотографии;
- решение `navigator.storage.persist()`;
- запуск Home Screen PWA после перезагрузки iPhone;
- VoiceOver и увеличенный системный размер текста;
- восстановление реальной рабочей `.bpsbackup` на отдельной тестовой установке.

До аппаратной приёмки резервная копия должна храниться отдельно от PWA.
